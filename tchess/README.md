# T-CHESS — Telegram-бот с мини-приложением

Шахматный бот с онлайн-партиями 1×1, тактическими задачами, турнирной статистикой
и профилем игрока (T-CHESS ID). Спонсоры **TikhonCHESS** и **Блог Шахматиста**
показаны баннером на главной и подписью внизу страниц.

## ⚠️ Сначала — про токен

Вы присылали токен бота в переписке. Как только всё заработает, зайдите к
[@BotFather](https://t.me/BotFather) → `/mybots` → выберите бота → **API Token** → **Revoke**,
чтобы выпустить новый токен. Старый нигде больше не используйте. Новый токен храните
только в файле `.env` (он уже добавлен в `.gitignore` и никуда не публикуется).

## Что понадобится

- Аккаунт в Telegram и доступ к [@BotFather](https://t.me/BotFather)
- Аккаунт на [Render.com](https://render.com) (бесплатно, карта не нужна)
- Аккаунт на [GitHub](https://github.com) — Render разворачивает сервис из git-репозитория

## Деплой на Render (рекомендуется)

Render даёт настоящий облачный сервер с постоянным HTTPS-адресом, который никогда
не меняется, и работает независимо от вашего компьютера — его можно выключить.
Единственная особенность бесплатного тарифа — сервис "засыпает" после ~15 минут
без запросов, первое обращение после сна грузится ~30–50 секунд. Подробнее — в
разделе [«Про бесплатный тариф Render»](#про-бесплатный-тариф-render) ниже.

**1. Залейте проект в GitHub**

Если ещё не сделано — создайте пустой репозиторий на GitHub и загрузите туда
папку `tchess` (через `git push` или прямо через сайт GitHub, кнопка "Add file →
Upload files"). Файл `.env` заливать не нужно и не надо — он и так в `.gitignore`.

**2. Создайте сервис на Render**

1. Зайдите на [render.com](https://render.com) → **New** → **Blueprint**
2. Подключите ваш GitHub-репозиторий с проектом — Render сам найдёт файл
   `render.yaml` и предложит настройки (они уже готовы в проекте)
3. Render попросит ввести переменную `BOT_TOKEN` — вставьте токен от @BotFather
4. Нажмите **Apply** / **Create** — начнётся первый деплой (2–3 минуты)

Если предпочитаете без Blueprint — **New → Web Service**, выберите репозиторий,
Build Command `npm install`, Start Command `npm start`, Instance Type **Free**,
и вручную добавьте переменную окружения `BOT_TOKEN`.

**3. Готово**

После деплоя Render покажет постоянный адрес вида `https://tchess-xxxx.onrender.com`.
Сервер сам подставляет его в переменную `MINI_APP_URL` (через `RENDER_EXTERNAL_URL`,
это делает Render автоматически) и сам подключает вебхук Telegram — ничего
руками прописывать не нужно. Откройте бота в Telegram и отправьте `/start`.

## Настройка кнопки мини-приложения в BotFather

1. `/mybots` → выберите бота → **Bot Settings** → **Menu Button** → **Configure Menu Button**
2. Отправьте адрес вашего сервиса на Render, например `https://tchess-xxxx.onrender.com`
3. Название кнопки, например: `♟ T-CHESS`

Теперь у бота внизу чата будет постоянная кнопка запуска мини-приложения, а команда
`/start` дополнительно пришлёт баннер со ссылкой на TikhonCHESS и Блог Шахматиста.
Адрес на Render не меняется при перезапусках/пробуждении — прописать его в BotFather
нужно один раз.

## Про бесплатный тариф Render

- **Сон после простоя.** Без запросов ~15 минут сервис засыпает. Бот работает через
  вебхук (а не long polling), поэтому даже "спящий" сервис проснётся от входящего
  сообщения в Telegram — просто первый ответ придёт с задержкой 30–50 секунд, дальше
  всё быстро, пока идёт активность.
- **Если хочется, чтобы бот совсем не засыпал** (например, для удобства во время игры
  с другом) — заведите бесплатный аккаунт на [UptimeRobot](https://uptimerobot.com)
  и добавьте HTTP-монитор на ваш адрес `https://tchess-xxxx.onrender.com` с
  интервалом проверки 5–10 минут. Регулярные запросы не дадут сервису уснуть.
  Это не обязательно, просто удобная опция.
- **Хранилище данных (рейтинг, история партий).** По умолчанию, если не задать
  `DATABASE_URL`, бот хранит всё в JSON-файлах в `data/` — а файловая система
  бесплатного тарифа Render эфемерная: эти файлы стираются при каждом передеплое
  и после долгого простоя (сна). Для дружеского теста это не страшно — рейтинг
  просто обнулится, сама игра продолжит работать как обычно. Если хочется, чтобы
  рейтинг и история не терялись — подключите бесплатную внешнюю базу Postgres
  (см. раздел [«Постоянное хранилище (Postgres)»](#постоянное-хранилище-postgres-опционально)
  ниже), это уже готово в коде, нужно только вписать один адрес подключения.

## Постоянное хранилище (Postgres, опционально, но настоятельно рекомендуется)

⚠️ Если вы столкнулись с тем, что рейтинг обнуляется — это почти наверняка
из-за того, что `DATABASE_URL` не задан. По умолчанию (без него) рейтинг,
аккаунты и история партий хранятся в JSON-файлах на диске сервиса, а на
Render (и большинстве бесплатных хостингов) диск эфемерный: файлы стираются
при каждом передеплое и часто — при пробуждении «уснувшего» бесплатного
сервиса. Подключите бесплатную
базу — например, [Neon](https://neon.tech) (2–3 минуты, карта не нужна):

1. Зарегистрируйтесь на [neon.tech](https://neon.tech) и создайте проект
   (бесплатного тарифа хватает с большим запасом для теста и небольшой группы игроков)
2. В панели проекта скопируйте **Connection string** — строку вида
   `postgresql://user:password@ep-xxxx.neon.tech/neondb?sslmode=require`
3. На Render: **Dashboard → ваш сервис → Environment** → добавьте переменную
   `DATABASE_URL` со скопированной строкой → **Save Changes** (сервис сам
   передеплоится с новой настройкой)
4. Для локального запуска — впишите ту же строку в `DATABASE_URL` в файле `.env`

При первом запуске сервер сам создаст нужные таблицы в базе — руками ничего
настраивать не нужно. Если `DATABASE_URL` не задан, всё продолжает работать как
раньше, на JSON-файлах — эту переменную можно оставить пустой и подключить базу
в любой момент позже, старые локальные данные из `data/` при этом не переносятся
автоматически (для дружеского теста это не важно — можно просто начать заново).

Подходит и [Supabase](https://supabase.com) — там тоже есть бесплатный Postgres
со строкой подключения в настройках проекта (Project Settings → Database →
Connection string, режим "URI").

## Локальный запуск (для разработки)

```bash
cd tchess
npm install
cp .env.example .env
```

Впишите в `.env` `BOT_TOKEN` и `JWT_SECRET` (любая случайная строка, например
`openssl rand -hex 32`) — без публичного адреса сервер сам включит режим long
polling, подходящий для локальной разработки:

```bash
npm start
```

Если нужно открыть мини-приложение локально в Telegram (не только тестировать API),
понадобится свой HTTPS-туннель — впишите его адрес в `MINI_APP_URL` в `.env`:
```
cloudflared tunnel --url http://localhost:3000    # или: ngrok http 3000
```

## Как это устроено

```
tchess/
├── server.js         # Express + WebSocket + Telegram-бот (вебхук на Render, long polling локально)
├── storage.js         # Хранилище: Postgres, если задан DATABASE_URL, иначе JSON-файлы
├── puzzles-seed.js    # стартовые задачи (загружаются один раз в пустое хранилище)
├── bot-pool.js        # пул потоков, в которых сервер считает ходы бота
├── bot-thread.js      # рабочий поток бота (worker_threads)
├── data/              # JSON-хранилище (fallback-режим без базы, создаётся автоматически)
└── public/
    ├── index.html      # разметка мини-приложения (3 страницы: Главная / Турниры / Профиль)
    ├── style.css        # оформление в стиле шахматного клуба
    ├── app.js            # вся логика: доска, задачи, матчмейкинг, профиль, админ-меню
    ├── chess.js           # шахматные правила для доски (ходы игрока, шах/мат/пат)
    ├── puzzlecheck.js     # проверка FEN и решения — общая для админ-меню и сервера
    ├── bot-engine.js      # шахматный бот (движок с поиском ходов) — и на сервере, и в браузере гостя
    └── bot-worker.js      # запускает бота гостя в фоновом потоке браузера (Web Worker)
```

**Онлайн-партии.** Игрок нажимает «Найти соперника» → сервер ставит его в очередь
и сразу же соединяет с первым подходящим соперником через WebSocket → оба клиента
проверяют ходы локально (библиотека `chess.js`), сервер их только ретранслирует и
считает изменение рейтинга (формула Эло) по завершении партии.

**Игра с другом.** Кнопка «Найти соперника» открывает выбор: «Играть с другом»,
«Найти случайного противника» (обычный поиск через очередь) или «Играть с ботом» (см. ниже). В режиме «с другом» сервер
выдаёт игроку 6-символьный код, который действует **10 минут**; под ним — поле «Введите
код друга». Друг вводит код у себя — и сервер сразу создаёт партию между ними (цвета
случайные). Подробности реализации:

- код одноразовый и удаляется при начале партии, нажатии «Назад», переходе на случайный
  поиск или по истечении 10 минут (тогда клиент автоматически получает новый код);
- алфавит кода без похожих символов (`0/O`, `1/I/L`), ввод не зависит от регистра;
- если приложение свернули (например, чтобы отправить код в чат) и сокет оборвался, код
  не пропадает: при возвращении клиент переподключается и «забирает» тот же код обратно
  по секретному токену, который знает только его владелец;
- защита от перебора: после 8 неверных кодов подряд ввод блокируется на 30 секунд;
- сервер раз в 30 секунд шлёт WebSocket-ping, чтобы прокси не закрывал «тихое»
  соединение, пока игрок ждёт друга;
- партия с другом **товарищеская**: рейтинг, статистика (сыграно / победы / серия) и история
  партий не меняются — сервер помечает такую комнату флагом `friend` и в `handleGameOver`
  ничего не сохраняет. В интерфейсе это видно по статусу «Игра с другом (без рейтинга)».

**Задачи.** Задачи хранятся в базе (Postgres) или в `data/puzzles.json` и управляются из
**админ-меню** в приложении. Стартовые 5 задач лежат в `puzzles-seed.js` и загружаются
**один раз** — при первом создании хранилища (иначе удалённые админом задачи «воскресали»
бы после перезапуска). Формат решения — ходы `{from, to}` **по очереди, начиная с хода
решающего**; ответы соперника тоже записываются, клиент играет их сам. Решение всегда
заканчивается ходом решающего (нечётное число ходов), поэтому «мат в 2» — это 3 хода.

- **Каждая задача засчитывается игроку один раз.** Решённая задача больше не выдаётся, а
  повторный запрос «я решил» даёт +0. Отметка «решено» ставится атомарно (первичный ключ
  `(uid, puzzle_id)` в Postgres), так что даже одновременные запросы не начислят рейтинг
  дважды. У гостей решённые скрываются по списку в `localStorage` (гостю рейтинг всё равно
  не сохраняется).
- Рейтинг за задачу (+4) начисляет только сервер, и только после запроса
  `POST /api/puzzle/solved` с правильными ходами решающего.
- Когда игрок решил все задачи, он видит сообщение; новые задачи от админа появляются у него
  сразу.

## Игра с ботом (с рейтингом или без — выбирает игрок)

«Найти соперника» → **Играть с ботом**. В открывшемся окне выбираются:
1. **Режим партии** — **«С рейтингом»** или **«Без рейтинга»** (переключатель вверху; выбор
   запоминается, как и уровень).
2. **Уровень** (**Лёгкий / Средний / Сильный**; запоминается).
3. **Цвет** — **Белыми / Случайно / Чёрными**. Цвет приложение спрашивает **каждый раз**, и при
   «Сыграть ещё раз» тоже: нажатие на цвет сразу начинает партию.

**«С рейтингом».** Очки считаются по Эло относительно рейтинга бота (K = 32, как в обычных
партиях): **Лёгкий — 700, Средний — 1100, Сильный — 1700**. Победа над слабым ботом почти ничего
не даёт (на 1200 очков: +2 за «Лёгкого»), над сильным — много, так что «накручивать» рейтинг на
лёгком боте бессмысленно. Победы, поражения, ничьи, серия и история партий обновляются как в
обычной игре (соперник в истории — «Бот · Средний»). Требует входа в аккаунт: если гость выберет
этот режим и нажмёт на цвет, приложение объяснит, что нужен вход, и откроет форму входа — тихо
переключать его на тренировку за него оно не будет. Рейтинги ботов — оценка их силы; правятся в
`BOT_RATINGS` в `server.js` (и те же числа в `BOT_RATINGS` в `public/app.js` и подписях карточек
уровней в `index.html`).

**«Без рейтинга».** Обычная тренировочная партия: рейтинг, статистика и история не меняются.
Доступна и гостю. У игрока с аккаунтом такая партия всё равно ведётся сервером (см. ниже) — просто
её результат нигде не сохраняется; в статусе партии и в итоговом сообщении видна пометка «без
рейтинга».

**Как рейтинговый режим защищён от подделки.** Игрок с аккаунтом (в обоих режимах) играет **под
контролем сервера**: сервер проверяет каждый ход по правилам, **сам выбирает ходы бота**, сам
определяет мат / пат / ничью, а для режима «С рейтингом» — сам считает рейтинг. Клиент только
показывает доску и присылает свои ходы — прислать «я выиграл» или подсунуть придуманную партию
невозможно.
- В режиме «С рейтингом» брошенная партия не бывает бесплатной: если игрок исчез и не вернулся за
  `BOT_IDLE_MS` (по умолчанию 15 минут), партии засчитывается **поражение**. «Перезапуск» начатой
  рейтинговой партии (новая партия при незаконченной старой) тоже засчитывает старую как
  поражение. Партия без единого хода игрока не засчитывается вообще; сдача засчитывается всегда.
  В режиме «Без рейтинга» ничего из этого не имеет значения — там просто нечего защищать.
- **Обрыв связи не страшен.** Партия (в обоих режимах, если игрок вошёл в аккаунт) хранится на
  сервере; приложение переподключается и забирает её обратно (то же — после перезагрузки страницы
  или закрытия приложения: незаконченная партия запоминается на устройстве и открывается сама).
  Если сервер перезапустили, партия теряется без последствий для рейтинга.
- Ходы бота считаются в **отдельных потоках** (`bot-pool.js`, `worker_threads`), поэтому «думающий»
  бот не тормозит остальных игроков; поток, который завис, убивается, а партия продолжается
  запасным ходом. Не более одной партии с ботом на игрока.

**Гость** (без входа в аккаунт) может играть только «Без рейтинга» — и делает это прямо в браузере
(сервер не участвует); рейтинг считается только в рамках текущей сессии и не сохраняется
(приложение об этом говорит).

**Движок** (`public/bot-engine.js`) — самостоятельный, не зависит от `chess.js`: доска 0x88,
поиск alpha-beta с итеративным углублением, просмотр взятий до «тихой» позиции, расширение при
шахе, оценка (материал, расстановка фигур, пара слонов, сдвоенные и проходные пешки, добивание
одинокого короля). Учитывает повторения и правило 50 ходов — в выигранной позиции не «ходит кругами».
Правильность генерации ходов подтверждена эталонными перфт-числами на шести стандартных позициях.
Уровни: «Лёгкий» смотрит только на свой ход и в трети случаев ходит наугад; «Средний» считает
2 полухода и взятия; «Сильный» — до ~6 полуходов, ограничено по времени (`BOT_L3_MS`).

Настройки сервера (необязательные переменные окружения):
- `BOT_L3_MS` — лимит времени на ход «Сильного» на сервере, мс (по умолчанию 1500). **На слабом
  хостинге (например, бесплатный тариф Render с долей процессора) поиск за это время дойдёт до
  меньшей глубины — бот будет играть слабее.** Если это заметно, увеличьте лимит или тариф.
- `BOT_WORKERS` — число потоков для расчёта ходов (по умолчанию 2 при нескольких ядрах, иначе 1).
- `BOT_IDLE_MS` — сколько партия ждёт пропавшего игрока до засчитывания поражения (только для
  режима «С рейтингом»; по умолчанию 15 минут).

## Тема оформления и доска

**Профиль → «Тема оформления»** — переключатель **Тёмная / Светлая**. Выбор применяется сразу,
запоминается на устройстве (`localStorage`) и применяется скриптом в `<head>` ещё до отрисовки —
поэтому при запуске не мелькает чужой фон. Обе темы — это наборы CSS-переменных в `style.css`
(`:root` и `:root[data-theme="light"]`); доска и фигуры в обеих темах одинаковые. По умолчанию —
тёмная. Основной текст в обеих темах читается с контрастом не ниже 7:1.

**Расцветка доски** соответствует правилам шахмат: поле **a1 — тёмное**, h1 — светлое (у белых
светлое поле справа внизу), ферзь стоит на поле своего цвета. Для чёрных доска просто
поворачивается, цвета полей те же.

## Админ-меню

Профиль → **⚙ Админ-меню** (кнопка видна только администраторам). Там можно **создавать,
редактировать и удалять** задачи: указать тему, позицию (FEN), решение и подсказку.
Решение можно вводить текстом (`e2e4 e7e5 g1f3`) или просто ходить по доске в редакторе —
ходы дописываются сами; кнопки «Убрать ход» и «Очистить» помогают исправлять. Редактор сразу
показывает ошибки (битый FEN, нелегальный ход, ход после мата, чётное число ходов) и не даёт
сохранить неверную задачу. Ту же проверку (`public/puzzlecheck.js`) **повторно** выполняет
сервер — в базу попадает только корректное.

**Кто администратор.** Задаётся переменной окружения `ADMIN_EMAILS` — e-mail через запятую
(на Render: Dashboard → сервис → Environment → `ADMIN_EMAILS`; локально — в `.env`).
Администратор входит в приложение своим обычным аккаунтом (e-mail + пароль). Права
проверяются на сервере при каждом запросе, поэтому убрать e-mail из списка — значит сразу
отозвать доступ.

⚠️ E-mail при регистрации письмом не подтверждается. Поэтому **сначала зарегистрируйте
аккаунт(ы) с админскими e-mail сами**, и только потом рассказывайте, кто админ — иначе
теоретически чужой человек мог бы занять этот e-mail раньше вас.

**Профиль / вход.** Аккаунт больше не привязан к Telegram — вход только по
e-mail и паролю (кнопка «Войти» в профиле открывает форму входа/регистрации).
Пароли хранятся в базе в виде bcrypt-хэша, сессия — JWT-токен в `localStorage`
браузера. Без входа приложение работает в гостевом режиме: партии и задачи
доступны, но рейтинг нигде не сохраняется (как и раньше без подтверждённого
аккаунта). Сам Telegram-бот остался — это по-прежнему способ открыть мини-приложение
(`/start` → кнопка «Открыть T-CHESS»), но для игры с сохранением рейтинга
внутри приложения нужно зарегистрироваться отдельно.

## Известные упрощения (MVP)

- Хранилище — JSON-файлы по умолчанию, с готовым переключением на Postgres
  через `DATABASE_URL` (см. раздел выше). Для совсем большой аудитории стоит
  добавить пул соединений/индексы под нагрузку — для дружеских тестов и
  небольшой группы игроков текущей схемы достаточно.
- Часы партии считаются на каждом клиенте отдельно (без строгой серверной синхронизации) —
  для дружеских онлайн-партий этого достаточно, но не подходит для турниров с призами.
- Исход онлайн-партии (человек против человека) сообщают сами клиенты, сервер не пересчитывает ходы. (Партии с ботом — исключение: их полностью ведёт и проверяет сервер.) Он проверяет,
  что итог прислал участник существующей партии и что партия засчитывается один раз, но
  не может доказать, что мат действительно был. Для турниров с призами нужна серверная
  проверка ходов.
- Если два человека одновременно нажмут «Найти соперника» из очень разных часовых
  поясов/рейтингов, бот всё равно их сведёт — сортировки по рейтингу для матчмейкинга нет.

## Добавление рекламных баннеров

Слайды баннера — в `public/index.html`, блок `.sponsor-banner`. Добавьте ещё один
`<div class="sponsor-slide">…</div>` по образцу существующих — карусель подхватит его
автоматически (см. `rotateSponsorBanner()` в `app.js`).
